# Ore is for Mining (Factorio mod)

Factorio 2.1 mod (Space Age optional): only mining drills, belts, underground belts, splitters, loaders, inserters, chests, beacons, power poles and pipes can be built on resource patches (ores and fluids like crude oil).

## How it works
- `data.lua` defines the `opr_resource` collision layer and the public `ore_is_for_mining` table other mods use to allow/block entities.
- `data-final-fixes.lua` adds that layer to resources and to every `player-creation` entity whose type isn't allowed, so the engine blocks placement (ghosts and blueprints included). Vehicles, trains, elevated rails and ghosts are never touched.
- Rules are type-based so modded entities are covered automatically.
- Rail supports and ramps count as rails: blocked unless `opr-allow-rails` is on. This is intended.
- Startup settings in `settings.lua`, text in `locale/en/locale.cfg` (setting names are `opr-*`).

## Testing
- `tests/run.sh` runs all scenarios against real prototype data from wube/factorio-data (2.0.77 and 2.1.20 by default, cached in `tests/.factorio-data/`).
- Add scenarios in `tests/scenario.lua` and list them in `tests/run.sh`.
- Requires Lua 5.2 (`lua`, `luac`), which matches the game's Lua version.

## Notes
- The game is installed on Windows. Mods folder: `C:\Users\Cristian\AppData\Roaming\Factorio\mods` (WSL: `/mnt/c/Users/Cristian/AppData/Roaming/Factorio/mods`). Install by copying `dist/<name>_<version>.zip` there and removing older zips of the mod.
- Repo: https://github.com/cristianwebber/ore-is-for-mining, pushed over SSH (`origin`, branch `main`).
- Release files: `changelog.txt` must keep Factorio's strict format (99-dash separator lines, 2-space category indent, 4-space `- ` entries). `README.md` is the mod portal description.
- `thumbnail.png` is generated by `tools/make_thumbnail.py` (standard library only) from the game's own sprites; it reads them from the Windows install at `D:\SteamLibrary\steamapps\common\Factorio\data` (or a data folder given as an argument); `--design` picks the layout (`split` is the published one; `outpost`, `icons`, `furnace`, `drill` are alternatives). The game and portal show it at 144x144, so tune it at that size. `tests/` and `tools/` don't belong in the release zip.

## Releasing
- Published on the mod portal: https://mods.factorio.com/mod/ore-is-for-mining (0.1.0 released 2026-09-27). The mod ID `ore-is-for-mining` can't change now, and every change the players get needs a new version.
- `python3 tools/release.py` validates (info.json, changelog, tests) and builds `dist/<name>_<version>.zip`. It never uploads without `--publish`.
- `--publish` needs `FACTORIO_API_KEY` in the environment. It publishes a new mod or uploads a release, then syncs the portal page. Never publish unless the user explicitly asks.
- The sync overwrites the portal's title, summary (`description` in `info.json`), description (`README.md`), category, tags, license, homepage and source link (both from `homepage`) with the repo's values (`CATEGORY`, `TAGS`, `LICENSE` in `release.py`). Make portal changes in the repo, or they are lost on the next release.
- For a new release: bump `version` in `info.json` and add a matching entry at the top of `changelog.txt`. After publishing, tag the released commit `v<version>` and push the tag.
